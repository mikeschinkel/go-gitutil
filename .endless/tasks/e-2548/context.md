Raised by Mike in gomion E-2540 planning on 2026-11-02. gomion's gompkg tests shell out to git directly (init, add, commit with fixed author env) from a test file; gomion also has its own gommod/gitutils package. Mike: git belongs in go-gitutil. Needed first by go-fsfix real repo fixtures and by gomion tests; mocking git is ruled out because it misses edge cases such as permissions.

Scope added from the go-fsfix brainstorm E-2547 (settled with Mike on 2026-11-06; its outcome holds the design). go-fsfix's RepoFixture now always creates a real repository and gains AddClone and AddWorktree, so the fixture operations go-gitutil must offer are: init with a branch name, forced add of every file, commit with a message and ident, clone, and worktree-add on a new branch. Ident is dt.Mailbox (a DisplayName of type dt.EmailDisplayName plus a dt.EmailAddress), which go-dt gains in a task filed from E-2547; go-gitutil defines no identity type of its own and names the field or parameter Ident. The add operation sets advice.addEmbeddedRepo=false so a fixture repo nested in another is recorded as an embedded repository without git's advice message. go-fsfix keeps the *Repo it used and returns it from RepoFixture.Repo(), so init must hand back a usable Repo without a second rev-parse.
